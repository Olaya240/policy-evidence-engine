## Unreached branches, ranked

1. **`STALE_NON_DIRECTIONAL_CONTEXT` (engine.py:239)** — a stale *accepted
   neutral* record is the only thing that emits this code, and no fixture has
   one. Everything that changes a verdict is covered; this one changes a
   disposition and is what an auditor reads when a neutral record ages out.
   *Pin:* one claim with `{"stance": "NEUTRAL", "days_old": 120}` and assert
   `["STALE_NON_DIRECTIONAL_CONTEXT"]`.

2. **`UNCLASSIFIED_REVIEW_REQUIRED` (engine.py:247)** — **unreachable today.**
   `EvidenceReviewState` has only `ACCEPTED` and `UNVERIFIED` (models.py:15-17),
   so every item takes one of the other six branches. The fallback is defensive
   code for an enum value that does not exist; if a `REJECTED` state is added it
   becomes the only branch that reports it, and nothing would notice a
   regression there.
   *Either* delete it with a note in the trace semantics, *or* pin it by
   constructing `Evidence(review_state=...)` through `model_construct` and
   asserting the code — the second documents intent, the first removes the dead
   path.

3. **`_iso_utc` naive input (engine.py:221)** — `value.astimezone(timezone.utc)`
   on a `datetime` with no `tzinfo` assumes *host local time*, so on a non-UTC
   host the trace's `generated_at` is offset by the host's zone while everything
   else in the record is UTC. Reachable through the injectable clock: an
   `AssessmentEngine(clock=lambda: datetime(2026, 1, 1))` produces a trace whose
   timestamp is silently wrong rather than rejected. Every other clock path is
   pinned; this one is not.
   *Pin:* `_iso_utc(datetime(2026, 1, 1))` is `2026-01-01T00:00:00Z` regardless
   of `TZ`, i.e. normalise naive to UTC (the same fix slice 6 applied to record
   timestamps).

4. **`_advisory_coverage_trace` per-category fields (engine.py:254-268)** — the
   test asserts the category *ids* and the two top-level flags. The
   `COVERED`/`NOT_COVERED` mapping, `matching_evidence_ids`,
   `fresh_accepted_*_ids`, `neutral_evidence_ids`, `unclassified_evidence_ids`
   and `independent_source_groups` are copied through unasserted, so a
   rename or a dropped key in `evidence_coverage` would leave the trace wrong
   while every test stays green.
   *Pin:* one claim with a support and a neutral record; assert
   `independent_checklist_support` is `COVERED` with that record id in
   `matching_evidence_ids`, and `checklist_access_context`'s state.

5. **`_evidence_dispositions` recomputes dependency (engine.py:232-237)** — it
   rebuilds `support_groups` and `dependent_ids` locally instead of reading
   `decision.dependent_support_ids`, which `_build_explanation_trace` already
   publishes. The two use the same representative rule *today* (last member per
   group) and nothing asserts that they agree, so a change to the decision's
   representative would make the trace contradict itself in the same document.
   *Pin:* assert `dependent_support_record_ids` equals the ids coded
   `DEPENDENT_SOURCE_GROUP` for a three-record group.

## Passing for the wrong reason

- `test_engine.py:88` asserts `summarize_status([a, b])[1] < .78`. The old
  diversity penalty produced 0.78; the signed table produces 0.5 or 1.0, so the
  assertion cannot fail for the quantity it was written to check. Harmless, but
  it no longer pins anything.
- The trace determinism test nulls `generated_at`, `decision_evaluated_at` and
  every `evaluated_at` before comparing. That is correct for "everything else is
  deterministic", but it means the injected-clock contract is only half pinned:
  no test asserts two *different* clocks produce different traces.
