## What each contract pins

1. `test_provider_error_category_is_read_from_the_code_attribute` — injects
   `ProviderError("synthetic_code_probe_7f31")`. `ProviderError.__init__`
   (`app/engine.py:38-43`) always raises with the fixed message
   "Assessment provider failed or returned invalid output", so a category taken
   from `str(exc)` or from the class name could never equal the sentinel. The sentinel appears in `cases[].error_category` and in
   `provider_error_rate.categories`, while the manifest attempt normalises it to
   `unexpected_exception` — normalisation therefore happens *after* `.code` was
   read. The exception message is also asserted absent from the whole payload.
2. `test_experiment_control_error_category_is_read_from_the_code_attribute` —
   same for the `ExperimentControlError` branch: injected
   `single_flight_limit` is reported as the category and in the manifest, and the
   message ("Experiment request was not authorized") is not the category.
3. `test_provider_failure_is_counted_in_every_bucket_it_belongs_to` — one
   injected `ProviderError("provider_failure")` on a case that scores 1/1 stance
   and 1/1 status and 1/1 quote in the clean run. Asserts denominators identical
   to the clean run, `provider_error_rate` = 1/17, the row survives with its
   `expected_stances`/`expected_status`, and stance/status/quote numerators fall
   by exactly those slots; abstention numerator unchanged and the case is not a
   valid abstention; `assessment_calls` unchanged (the failed attempt consumed
   its single reserved request) and the manifest still has 17 attempts.
4. `test_reported_accuracy_is_recomputable_from_the_reported_rows` — guarded
   (shipped default) run; recomputes stance, status and per-provider-mode
   numerators/denominators/rates **only** from `result["cases"]`, and asserts the
   row set without `expected_stances` is exactly the 4 dataset contract cases
   (they own no model slots), with denominators equal to the row label counts.
5. `test_evaluation_does_not_touch_the_configured_persisted_database` — points
   `HACKATHON_DB_PATH` at a sentinel DB inside `store.DATA_DIR` (40 960 bytes, 12
   records), runs a full evaluation, and asserts bytes identical, `list_records()`
   identical, env restored to the caller's path, no new `.phase37-eval-*` files,
   and `deterministic_recomputation_history_consistency.disposable_database_removed`
   true with `passed == total > 0`.
6. `test_evaluation_instant_is_normalised_at_construction_and_honoured_by_the_engine`
   — constant is aware UTC with zero offset (`isoformat` ends `+00:00`); `now()`
   returns naive UTC and the same instant for an aware tz (`+05:00`);
   `patch("app.engine.datetime", EvaluationDateTime)` makes the engine stamp
   `generated_at == "2026-10-27T12:00:00Z"`, while the same engine without the
   patch stamps within 60 s of `datetime.now(timezone.utc)`.

## Findings

- **`.code` is real and is what the harness reads.** `Read` —
  `app/evaluate.py:206` (`except ProviderError as exc: error_category = exc.code`),
  `:208` (same for `ExperimentControlError`), `:182` (contract branch reads
  `exc.code` as the rejection code); `Observed` by the sentinel probe above: the
  raw code reaches the row and `provider_error_rate.categories` while the same
  attempt is normalised to `unexpected_exception`.
- **A provider failure is counted, never swallowed.** `Observed` — denominator
  fixed at 17 cases / 18 stance labels, failed case keeps a row and scores its
  gold slots as wrong, is excluded from valid abstentions, and still consumes one
  reserved request (`assessment_calls` = 17/17).
- **Reported accuracy is the accuracy the reported rows support.** `Observed` —
  full recomputation from `cases[]` matches `stance_accuracy`,
  `status_accuracy`, `by_provider_mode` and `expected_denominators` exactly in
  the guarded default run.
- **The persisted database is not mutated.** `Observed` — byte-identical
  40 960-byte sentinel, 12 records before and after, env restored, disposable DB
  and its `-journal`/`-wal`/`-shm` siblings removed. Discriminator run: a
  sabotaged `_evaluate_recomputation_history` that writes the configured DB made
  the byte comparison change (`bytes changed: True`), so assertion 5 can fire.
- **`EVALUATION_AS_OF` was flagged for not being normalised at construction; that
  does not reproduce.**  `Read` — `app/evaluate.py:21` is
  `datetime(2026, 10, 27, 12, tzinfo=timezone.utc)`, i.e. aware with offset zero;
  `EvaluationDateTime.now(tz=None)` normalises to naıve UTC rather than host-local
  (observed `2026-10-27 12:00:00`), and `now(tz)` returns the same instant. The
  engine's default clock (`app/engine.py:425`, lambda resolving module-global
  `datetime`) is frozen by the patch, so the flag is a missing test rather than a
  behaviour. Now pinned by test 6.
- **Residual, not acted on (outside this slice’s scope):** the frozen instant
  covers `app.engine.datetime` only. `app/store.py:158` (`create_investigation`)
  and `:239` (`apply_challenge` history) call
  `datetime.now(timezone.utc)` directly, so rows written into the disposable DB
  carry wall-clock timestamps even though engine stamps are frozen. `Observed`
  that neither enters `checks`, so
  `deterministic_recomputation_history_consistency` is unaffected; the comment at
  `app/evaluate.py:57-60` ("The clock is injected for the whole run") is narrower
  than it reads.
