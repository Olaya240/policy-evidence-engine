in three separate comprehensions. On these four dimensions the two files agree.

## Divergences, ranked

### D1 — three independent implementations of the same grouping (high)

The engine writes the grouping rule three times in one function:

- `:115` `independent_support = len({...})` — feeds the verdict
- `:118-120` `group_members` — feeds `independent_groups` and the dependency list
- `:211-214` `support_groups` inside `_evidence_dispositions` — feeds the audit trail

All three are textually identical today, which is exactly why nobody will notice
when one changes. The disposition trail's `dependent_ids` is computed from a
*second* dictionary, so a divergence there would show the user one set of
"dependent" records while the verdict was decided on another. This is the highest
structural risk in the slice: not a bug, but a single edit away from one.

### D2 — the "as if the dispute were settled" count is a sum, not a union (high)

`decide(s, c, disputed_support=ds, disputed_contradiction=dc)` evaluates the
challenged label at `_label(s + ds, c + dc)`. That is only correct if the disputed
groups are disjoint from the counted groups. They need not be: a group with one
undisputed support record and one *disputed* support record is counted at `:115`
(through the undisputed record) **and** at `:145` (through the disputed one).

Concrete, and checkable in one probe:

- group A has a fresh accepted support (undisputed) and a second fresh accepted
  support that a reviewer disputed → `s = 1`, `ds = 1`
- excluded view: `(1, 0)` → PARTIAL, score `0.5`
- as-if view used by the code: `(2, 0)` → SUPPORTED, score `0.667`
- labels differ, so the claim is downgraded to PARTIAL but **reports 0.667**,
  the number the code computed for a two-group world that does not exist

If the challenge is upheld the claim stays PARTIAL 0.5; if it is rejected the
group count is still 1, so it stays PARTIAL 0.5. The only reachable truth is 0.5,
and the reported 0.667 is unreachable — the same class of defect as the original
collision, arriving through the dispute path. The fix belongs in the table (take
group *sets*, or the evidence itself, and union before evaluating), not in the
engine.

### D3 — `MIN_SUPPORT_GROUPS` is hardcoded in the advice text (medium)

`:176` emits `"An independent, recent corroborating source…"` guarded by
`independent_support < 2`. The verdict uses the policy constant. If anyone selects
`POLICY_TWO_TO_ONE` (`min_support_groups = 1`) the claim can read SUPPORTED while
`missing` still asks for corroboration it no longer requires. Import the constant.

### D4 — the engine can never choose a policy (medium)

`decide_table(...)` at `:144-149` passes counts and dispute numbers only. No
`policy=`, so `POLICY_CONTEST_BLOCKS` and `POLICY_TWO_TO_ONE` are dead outside
tests. The engine is bound to the default by omission rather than by a declared
choice, and `policy_id` can never vary in production. Either thread a policy
through `AssessmentEngine` or delete the alternatives; leaving both is how a
"configurable" policy becomes a fiction.

### D5 — `diverse` and `departments_by_source` are dead (low, but visible)

`:116-117` build `departments_by_source` and `diverse`; nothing reads either after
v2, because the table no longer takes diversity. The trace still records
`department_diversity_uses_last_support_record_per_group: true`, so an auditor
reading the trace is told a diversity rule is in force when the verdict ignores it.
Either wire diversity into the table or drop both the variables and the trace key.

### D6 — `is not` versus `==` on the review state (low)

The table skips with `item.review_state is not EvidenceReviewState.ACCEPTED`; the
engine filters with `==`. Identical for enum members, divergent the moment a plain
string reaches the table (a hand-built test double, a dict that skipped
`model_validate`). Type says enum, so this is latent only.

### D7 — "one place that counts" is not true of the engine (low)

`contradiction_groups` is recomputed inline at `:134` rather than through
`decision_table`'s helper, and `independent_support` at `:115` likewise. The
table's docstring describes itself as the counting authority; today it is the
counting authority for the *formula* only. Worth a single `count_groups(evidence)`
used by both, which would also collapse D1.
