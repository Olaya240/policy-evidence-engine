## The partition, as written

| set | rule as coded |
|---|---|
| `fresh` | `not e.stale` |
| `accepted` | `fresh` **and** `review_state == ACCEPTED` |
| `supports` | `accepted` **and** `stance == SUPPORTS` **and** `not e.disputed` |
| `contradicts` | `accepted` **and** `stance == CONTRADICTS` **and** `not e.disputed` |
| `neutrals` | `accepted` **and** `stance == NEUTRAL` — **no disputed filter** |
| `stale_accepted` | `e.stale` **and** `review_state == ACCEPTED` (disputed allowed) |
| `stale_support` / `stale_contradictions` | split of `stale_accepted` by stance |
| `disputed` | `e.disputed` — every review state, every age |
| `unverified` | `review_state == UNVERIFIED` — every age |

`independent_support = len({e.source_group or e.source_record_id for e in supports})`, i.e.
distinct groups among *undisputed fresh accepted supports*. The `or` fallback means a record
with an empty `source_group` is its own group, and two records sharing a group count once.

## Shapes that land in two sets at once

1. **Fresh, accepted, disputed, SUPPORTS** → in `disputed` and in `disputed_fresh_accepted`
   (used for the challenge-view label), not in `supports`. Intended: the record is excluded
   from the verdict and re-admitted only to test whether the dispute is decision-relevant.
2. **Fresh, accepted, disputed, NEUTRAL** → in `neutrals` *and* `disputed`. This is the only
   shape that is simultaneously "counted as accepted non-directional evidence" and "under
   challenge". It reaches the uncertainty fallback (`... if not evidence or neutrals`) and the
   `NEUTRAL_NOT_DIRECTIONAL` disposition code.
3. **Stale, accepted, disputed, SUPPORTS** → in `stale_accepted`, `stale_support` *and*
   `disputed`; it is reported twice in `conflicts` (stale-context sentence and challenge
   sentence).
4. **Stale, unverified** → in `unverified` only, never in `accepted`; it still reaches
   `disputed` if challenged.

## Findings, ranked

### 1. `neutrals` is the one partition that ignores `disputed` (asymmetry)
`supports` and `contradicts` both exclude disputed records; `neutrals` does not. A challenged
neutral record therefore still counts as accepted non-directional evidence: it changes the
fallback uncertainty sentence from "No admissible, relevant evidence..." to "Only stale or
non-decisive evidence is available", and it carries `NEUTRAL_NOT_DIRECTIONAL` alongside
`DISPUTED_REVIEW_REQUIRED` in the dispositions.

Impact is presentational, not numeric — the signed table counts only directional groups, so no
score moves. But the rule "a challenged record is not uncontested evidence" has an exception
nobody wrote down, and the exception is exactly the state an auditor would ask about.

Cheapest fix: add `and not e.disputed` to `neutrals`, and let the disputed-neutral shape fall
into the `else` branch. That makes all four partitions apply the same exclusion.

### 2. `diverse` is computed and never used, while the trace still advertises it
`diverse` is derived from `departments_by_source` (last support per group) and then not
referenced anywhere in the file. v2 dropped the department bonus from the score, so this is
v1 residue. Meanwhile `_build_explanation_trace` still emits
`"department_diversity_uses_last_support_record_per_group": True`.

That is provenance that no longer exists: a reader debugging a `0.667` is told the
last-record-per-group rule fed department diversity into the verdict. It did not — diversity
never reached the table. Either delete the flag and the dead computation, or re-introduce
diversity deliberately; leaving both is worse than either.

### 3. `disputed` spans review states and ages, so `conflicts` can cite inadmissible evidence
The sentence "The user challenged evidence from X" is built from `disputed`, which includes
unverified and stale records. Only `disputed_fresh_accepted` affects the verdict. So a claim
can read `INSUFFICIENT` with a conflict line naming a record that was never accepted — true,
but it reads as though accepted evidence were in play. Same for stale disputes, which are
already covered by the stale sentence (double-reporting).

Cheapest fix: word the challenge sentence from `disputed_fresh_accepted` and add a separate
"challenged but not yet accepted" clause for the rest, so the two audiences (verdict, reviewer)
see different statements.

## Does `contested` agree with `status`?

`contested` is `(s > 0 and c > 0) or disputed > 0` from `decision_table`. It can be `True`
alongside `SUPPORTED` — the 4-support-1-contradiction shape — and that is intended: the
uncertainty text adds "the sources disagree in direction and the support outweighs it".

It cannot be `True` alongside `INSUFFICIENT` for a *directional* dispute: with `s = c = 0` and
one disputed directional record, the challenged label differs (`PARTIAL` or `CONTRADICTED`), so
the downgrade forces `PARTIAL`. A disputed *neutral* sets no disputed group count, so
`contested` stays `False`. So `contested ⇒ status ≠ INSUFFICIENT` holds — and is worth pinning
with a test, since it is currently an emergent property of two files.

## Also worth recording

`stale` is a snapshot, not a predicate: `_validate_assessment_with_time` writes
`stale = age > STALE_DAYS` once, and `_summarize_status_decision` trusts `e.stale`. A stored
claim replayed after another year still reports "fresh", while the trace's `staleness_policy`
reports a `threshold_days` / `comparison` rule as though it were re-derived at read time. If
the policy is meant to be frozen at evaluation, the trace should say "evaluated_at" is the only
clock; if it is meant to be live, the flag has to be recomputed.
