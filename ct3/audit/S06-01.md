## Three findings, ranked

### 1. A timezone-naive `Record.timestamp` turns every assessment into an unclassified `TypeError` — Inferred, high

`_validate_assessment_with_time` computes

```
age = (evaluated_at - record.timestamp).days
```

with `evaluated_at = now if now is not None else datetime.now(timezone.utc)`. The
left side is always offset-aware. `Record.timestamp` is declared as a bare
`datetime` in `app/models.py:138` with no validator, and pydantic parses a naive
ISO string (`"2026-01-01T09:00:00"`) into a naive `datetime`. Subtracting a naive
from an aware datetime raises `TypeError: can't subtract offset-naive and
offset-aware datetimes` — not an `AssessmentError`, so it surfaces as an
unclassified 500 rather than a controlled `invalid_source`/`invalid_quote`.

Whether it is reachable depends on what the store writes; every fixture I saw is
aware. The fix is one line either way: normalise on ingest
(`timestamp = timestamp if timestamp.tzinfo else timestamp.replace(tzinfo=timezone.utc)`)
or reject with a coded `AssessmentError`. The second is safer — a missing offset is
a data defect, not a defaultable field.

### 2. Staleness is one-directional: a future-dated record is never stale — Read, latent

`stale=age > STALE_DAYS` with `age = (evaluated_at - record.timestamp).days`. A
record dated 2099 produces `age` of about −27,000, so `stale` is `False` forever and
the record counts as fresh current proof. Nothing else in the slice bounds
`record.timestamp` in either direction.

This matters for an audit product: a mis-typed year silently promotes the record to
live evidence, and the same arithmetic silently accepts a record stamped a minute
into the future. A clamp (`max(age, 0)` does **not** fix it — it hides it) or an
explicit `invalid_timestamp` code for `timestamp > evaluated_at` are the two honest
options; the second is preferable because the record is not merely "new", it is
inconsistent with the clock being used to judge it.

### 3. `diverse` and `departments_by_source` are dead after the v2 rewrite — Read, cosmetic

```
departments_by_source = {e.source_group or e.source_record_id: e for e in supports}
diverse = len({getattr(e, "department", None) for e in departments_by_source.values()}) > 1 ...
```

`diverse` is assigned and never read anywhere in the module (the only other
occurrence is the definition); `departments_by_source` exists only to feed it.
Department diversity stopped affecting the score when the branch table was replaced
by `decision_table`, which is correct, but two live-looking computations now imply a
rule that no longer exists. Removing them removes the implication.

## Smaller items, with the exact text

- **`_StatusDecision` has no invariant.** It is a plain mutable `@dataclass` with no
  `__post_init__`, so `status=SUPPORTED, confidence=0.0, evidence_score=-1.0` is a
  constructible value. It is internal, but it is the structure the explanation trace
  is derived from, and `confidence == abs(evidence_score)` is only true because one
  call site happens to build it that way.
- **Disputed neutrals are counted as neutral.** `supports` and `contradicts` both
  carry `and not e.disputed`; `neutrals = [e for e in accepted if e.stance is
  NEUTRAL]` does not. A challenged neutral therefore still counts toward the
  "accepted non-directional evidence" text path. Small, but it is the only place in
  the three filtrations that forgets the dispute flag.
- **`_iso_utc` trusts its argument.** `value.astimezone(timezone.utc)` on a naive
  datetime assumes system local time and returns a wrong instant with no error. It
  is only safe because callers pass `evaluated_at`, which is aware today; the
  function does not say so.
- **`age` truncates.** `.days` floors, so a record 90 days and 23 hours old reports
  `90` and is not stale under `> STALE_DAYS`. Defensible, undocumented.
- **Grounding is a 3-character substring**, identical to the provider-side check
  (`len(quote.strip()) < 3 or quote not in record.text`). Same weakness the slice-4
  audit recorded: `"the"` grounds a proposal. Consistent across both boundaries,
  which is worth knowing before changing one of them.
- **The module docstring says "Deterministic".** True only when a clock is injected;
  the default path still reads `datetime.now`. Not wrong, but the first line of the
  file now overstates what the module guarantees by default.
