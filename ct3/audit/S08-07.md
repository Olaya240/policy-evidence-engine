## Non-vacuity: each assertion run against a mutated engine

Four throwaway copies of `backend/` were made under `/tmp` (the repository copy was
not touched) and the test file run against each.

| Mutation | Result |
|---|---|
| `challenge` uses neither the preserved prior decision nor the new one (`if False`) | **FAIL** — `test_challenge_appends_a_real_guard_decision_and_covers_every_item`: `assert 'PRIOR_GUARD_DECISION_UNAVAILABLE' != 'PRIOR_GUARD_DECISION_UNAVAILABLE'` |
| staleness table built over `evidence[:-1]` | **FAIL** — `test_staleness_table_has_one_row_per_evidence_item`: `assert 1 == 2` rows |
| `_claim` records one `evaluation_times` entry for two evidence items | **FAIL** — `test_fresh_claim_has_no_unknown_missing_evaluation_time_row`: index 1 basis is `UNKNOWN_MISSING_EVALUATION_TIME` |
| `_build_explanation_trace` truncates with `evidence[:len(evidence_evaluation_times)]` (the old `zip` shape) | **PASS** — recorded honestly, see below |

The last row is not a hole in the test, it is a fact about the code: through
`_claim` and `challenge` the two lists are index-parallel by construction —
`evaluation_times.append(evaluated_at)` sits inside the same `if key not in seen:`
block as `evidence.append(item)` (engine.py:508-513), and `challenge` appends
exactly once per `evidence_models` entry inside one `enumerate` loop
(engine.py:585, 621) — so `len(evaluation_times) == len(evidence)` always holds and
the truncating form is a no-op on these two paths. Contract (c) is therefore
pinned against a table that *drops* a row (which does fail), not against the
`zip` shape, which cannot be produced here. A future caller that passes a short
list would still be caught, because `_staleness_row` names
`UNKNOWN_MISSING_EVALUATION_TIME` and test (d) forbids it in `_claim` output —
but test (d) only fails if `evaluation_times` becomes short, which the mutation
above demonstrates it does.

## What these tests do not cover

- **`generated_at` on the `challenge` path.** (e) is scoped to a fresh `_claim`
  only, as briefed. `challenge` stamps `_iso_utc(now)` from the injected clock
  (engine.py:622-625) but no assertion here ties the challenged trace's
  `generated_at` to the clock, so a second wall-clock read there would not fail
  this file. Flagged, not tested; fixing or testing it is outside this worker's
  one-file scope.
- **Ordering beyond `source_record_id`.** Duplicate `source_record_id` values
  would let the row lists compare equal while describing different items; the
  seed fixture has unique ids, so this branch is not exercised.
- **`PRIOR_GUARD_DECISION_UNAVAILABLE` reachability for a genuinely legacy
  claim** — a stored trace with an empty `decisions` list was exercised once in
  the diagnostic script (`legacy decisions: [('OPS-101','PRIOR_GUARD_DECISION_UNAVAILABLE'), ('OPS-110','PRIOR_GUARD_DECISION_UNAVAILABLE')]`, and staleness basis `PRESERVED_STORED_STALE_FLAG`), which proves the forbidden string is producible and the assertion can fire; it is not a test in this file.
- **Persistence, routes, HTTP status.** No store, route or revision check is
  touched here; slice 8's other workers own those.
