## Ranked findings

### 1. The trace's staleness policy now describes a rule the code no longer runs — Read (`:355-372`)

```python
"comparison": "AGE_DAYS_GREATER_THAN_THRESHOLD",
"timezone": "UTC",
"decision_evaluated_at": _iso_utc(generated_at),
```

The validator is `stale = age > STALE_DAYS or age < 0` (slice 6). Three false statements
in one block, all persisted into every claim:

- `comparison` omits the negative-age arm, so a consumer recomputing staleness from the
  trace will call a future-dated record fresh when the engine called it stale;
- `timezone: UTC` claims a normalisation the code only applies to offset-less rows
  (`engine.py:56-58`), and says nothing about it;
- `decision_evaluated_at` is `generated_at` — when the trace was written — not the
  `evaluated_at` each evidence row was actually judged against, which the same block
  reports per row under `basis: ASSESSMENT_VALIDATION`. One field says "the decision time
  is now", its sibling says "the decision time was then". Both cannot be the answer.

Traces are the audit artifact; a trace that overstates its own rule is worse than no trace.

### 2. The engine's immutability contract is enforced by a guard, not by the type — Read (`:386-398`)

```python
__slots__ = ("provider", "provider_boundary", "semantic_guard", "clock", "_sealed")

def __setattr__(self, name, value):
    if getattr(self, "_sealed", False):
        raise AttributeError("assessment engine configuration is immutable")
```

`object.__setattr__(engine, "provider_boundary", other)` succeeds and replaces the
`MandatoryProviderBoundary` that `_provider_assess` then calls (`:404`). No `__delattr__`
either, so `del engine.provider` also succeeds and leaves a half-built engine whose next
`_provider_assess` raises `AttributeError` — an unclassified 500 rather than a controlled
error. Only in-process code can do this, so it is a contract defect, not a remote hole;
it matters because the error message promises a property the type does not have, and
because the boundary is the one component whose substitution must be impossible.

### 3. `_evidence_dispositions` re-implements the grouping rule it is supposed to report — Read (`:238-250`)

It rebuilds `support_groups` and takes `members[:-1]` as dependent, duplicating
`_summarize_status_decision:115-120`; `decision.dependent_support_ids` already holds that
answer. Two copies of one rule are one edit apart from a trace that contradicts the
verdict — the same defect class as the triple grouping recorded in `S06-03`. Membership is
by `id(item)`, so a `model_copy()` of an Evidence (same record, different object) lands in
`UNCLASSIFIED_REVIEW_REQUIRED` while being counted by the decision.

### 4. `_iso_utc` silently assumes the host's local zone for a naive value — Read (`:222-224`)

`value.astimezone(timezone.utc)` on a naive datetime interprets it as local time. An
injected naive clock (`AssessmentEngine(clock=lambda: datetime(2026,1,1))`) therefore
produces a trace whose `generated_at` shifts with `TZ`; the slice-6 fix normalised the
evidence timestamps but `generated_at` still comes straight from `self.clock()`.

### 5. `department_diversity_uses_last_support_record_per_group: True` is provenance for nothing — Read (`:332`)

`diverse` and `departments_by_source` are computed and read by no branch since the signed
table took group counts only (slice 6). The trace advertises a rule that no longer moves
the verdict.

### 6. `permitted` is computed and not passed, under a comment that claims it is the boundary — Read (`:399-404`)

```python
permitted = eligible_provider_records(records)
indexed = {record.id: record for record in permitted}
proposals = self.provider_boundary.assess(records, hypothesis_id)
```

The boundary projects for itself (slice 5), so behaviour is right today; but the local
name plus "This is the final permission boundary before any provider sees records" reads
as though `permitted` were the argument. It is a trap for the next refactor rather than a
live hole.

## Checked and correct

- `except Exception -> ProviderError("provider_failure")` does not catch `CancelledError`
  (`BaseException` since 3.8), so cancellation still propagates; the detail-hiding is
  deliberate and does not swallow the code when the failure is a `ProviderSafetyError`.
- `set(proposal) != {four keys}` is an exact re-check of the boundary's contract on the
  local side too; a proposal that gained a field is refused rather than trimmed.
- `_score_direction` is the single source of the `FOR`/`AGAINST`/`NONE` mapping, so a
  trace and a claim cannot disagree about the sign.
