## 3. Tests that assert nothing, or pass for the wrong reason

1. **`test_engine_slice8_provider.py::test_non_list_proposals_result_is_malformed_output`** (4 params) — its
   docstring says it pins `engine.py:433-434`. It does not: every param runs `426→428` only, and 433/434 never
   execute in any test. The `malformed_output` code comes from `provider_safety.py::_validate_provider_proposals`
   (via `MandatoryProviderBoundary.assess`). Green, but pinning the boundary, not the engine. Verified by running
   those 4 params under the counter: `{'426': 1, '428': 1}` and no 433/436 keys.
2. **`test_engine_slice8_provider.py::test_proposal_key_set_must_match_the_four_key_contract`** (5 params) — same
   shape; engine's own 4-key check at 436/437 never runs.
3. **`test_engine.py::test_provider_proposals_with_unknown_sources_bad_quotes_or_bad_shape_fail_closed`** (4
   params) — bare `pytest.raises(ProviderError)` with no `.value.code` assertion, although the name names three
   distinct refusals (`invalid_source`, `invalid_quote`, `malformed_output`). All 4 params take `426→428`. It would
   stay green if the engine collapsed every refusal into one code.
4. **`test_engine.py::test_staffing_guard_outcomes_keep_engine_proposals_for_review`** — computes its expected
   state with `reviewed_relation(quote, "STAFFING_CONSTRAINTS")`, the same helper `_review_item_with_trace` calls at
   line 465. Self-referential oracle: a wrong cue table moves the expectation with the behaviour. Only a change that
   stopped calling the helper would fail it.
5. **`test_engine.py::test_neutral_and_directional_guard_proposals_require_matching_explicit_cues`** — the status
   assertion is `Status.INSUFFICIENT` in *both* arms (`:626` for ACCEPTED, `:630` for UNVERIFIED), so it
   discriminates nothing; the real oracle is `review_state` at `:622`.
6. **`test_engine_slice8_trace.py:49` and `:75`** — `assert row["reason_code"] != "PRIOR_GUARD_DECISION_UNAVAILABLE"`
   is negative-only: any other string, including a wrong one, passes. These are the only tests anywhere near the
   replay path (601-613) and they cannot detect a wrong reason code.
7. **`test_engine_purity.py::test_challenge_does_not_rewrite_a_legacy_claim_it_was_handed`** —
   `assert all("review_state" in item for item in revised["evidence"])` is vacuously true if `evidence` is empty.
   Measured for its own fixture: evidence = 2 items, so non-vacuous *today*, but nothing pins it (adding
   `assert revised["evidence"]` would).
8. **`test_legacy_challenge.py::test_a_pre_upgrade_investigation_can_still_be_challenged`** — same pattern:
   `assert all("review_state" not in item …)` is vacuous if every stored claim's evidence list is empty, and the
   test's whole premise ("legacy rows lack review_state") rests on it. I did not measure the store-seeded fixture
   (needs `store.initialize_database()`, which only the fixture does), so: currently unverified rather than proven
   vacuous.

No test in the suite is a bare `assert True` / no-assertion test in this range; the problems above are weak oracles
and shadowed branches, not empty tests.

## 4. Ranked untested contracts (each with the one-line test that pins it)

1. **Replay across a reordered evidence list** (`engine.py:588` false arm, body 591-600, 0 executions). Today the
   only replay case tested is "same record at same index". If a claim's evidence order differs from the stored
   trace's decision order — the legacy re-save path that produced the original 409 — the engine is supposed to drop
   the prior decision and re-derive. Nothing checks it.
   *Test:* challenge a 2-item claim, swap the two `explanation_trace.semantic_guard.decisions` rows, challenge
   again, assert the mismatched index carries `reason_code == "PRIOR_GUARD_DECISION_UNAVAILABLE"` and
   `decision_source == "PRESERVED_LEGACY_EVIDENCE"` while `review_state` still comes from the item.
2. **`_provider_assess`'s own fail-closed checks** (433-437, 440-445; unreachable by construction — the boundary
   validates the same four constraints first). Either pin it or delete it; as it stands it is a contract no caller
   can violate and no test can reach.
   *Test:* `monkeypatch.setattr(type(engine.provider_boundary), "assess", lambda self, records, hid: "not-a-list")`
   then `with pytest.raises(ProviderError) as e: engine.assess_hypothesis(records, HID)` and
   `assert e.value.code == "malformed_output"` — the only route to line 434.
3. **`_claim(extra=...)`** (497-498; 0 executions; parameter unused everywhere). Contract implied by the signature:
   extra proposals are appended after provider evidence and participate in dedup, status and trace.
   *Test:* `engine._claim(HID, HID, records, extra=[{"source_record_id": …, "quote": …, "stance": "CONTRADICTS", "rationale": "…"}])`
   and assert the item appears in `evidence` and in `explanation_trace.semantic_guard.decisions`. Or drop the
   parameter.
4. **`_review_item` compatibility wrapper** (490-492; 2 calls in 1 test; no production caller). Nothing pins that
   the wrapper's returned item is the same item the trace describes.
   *Test:* for both `semantic_guard` settings, assert `engine._review_item(item_a, HID).model_dump() ==
   engine._review_item_with_trace(item_b, HID)[0].model_dump()` on identical inputs.
5. **`__setattr__` fall-through** (416 false → 418; 0 executions, and unreachable through the public API because
   `__init__` writes via `object.__setattr__` and seals last). Dead defensive branch unless a subclass hook is
   intended.
   *Test (only if subclassing is intended):* a subclass calling `self.anything = 1` before `super().__init__()`;
   otherwise delete 418.

Lower rank, noted not ranked: the NEUTRAL-match arm (471) has exactly one execution in the suite; the two
`reason_code != …` assertions in `test_engine_slice8_trace.py` should become `==` with the expected code.
