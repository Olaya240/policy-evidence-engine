## Findings, ranked

1. **`Decision.disputed_groups` has no consumer in the slice** (`decision_table.py:282`,
   read by nothing; engine `:205` takes only `decision.score` and `decision.contested`).
   The consequence is presentational but real: a stale or unverified challenged record
   leaves `decision.contested` False (it is computed from `reported_disputed`,
   `decision_table.py:284`) while the claim's `conflicts` text names the challenge and
   the dispositions mark `DISPUTED_REVIEW_REQUIRED`. An auditor reading `contested:false`
   beside a disposition that says a review is required has no way to tell which is the
   intended answer. Either surface the count in `_StatusDecision` or drop it.

2. **The trace advertises a diversity rule that does not run** (`engine.py:327`,
   `department_diversity_uses_last_support_record_per_group: True`). `departments_by_source`
   and `diverse` are computed at `:126-128` and read by nothing after the signed table
   took group counts only. This is provenance for a computation that no longer feeds
   the verdict — worse than deleting it, because a reader trusts it.

3. **`decision_evaluated_at` is `generated_at`** (`:362`), while the per-evidence block
   two lines below reports the real assessment-time `evaluated_at` (`:365-373`). In
   `challenge` and `investigate`, `generated_at` is the trace time, not the instant
   staleness was judged, so the field is mislabelled. It matters because `_iso_utc`
   (`:221-222`) calls `.astimezone(utc)` on whatever it is given: for a naive datetime
   that silently uses the host's local zone, so `"timezone": "UTC"` (`:359`) is a claim
   the conversion does not guarantee for injected clocks.

4. **`_evidence_dispositions` re-implements the dependency rule** (`:230-236`): it
   rebuilds `support_groups` from `decision.supports` and takes `members[:-1]`, while
   `_summarize_status_decision` already computed the same set at `:134-135`. They agree
   today only because both walk the same list in insertion order. That is also what makes
   the "dependent" record order-dependent: reversing the evidence list moves the label to
   a different record, though `decide_evidence` is tested for order-independence. One
   helper, two call sites, would remove the class.

5. **Residual double count between directions** (`:168-171`): the disputed sets are
   deduplicated against the undisputed counts but not against each other. A group holding
   a challenged support *and* a challenged contradiction is added to both sides of the
   as-if denominator, so one source reads as two. It is directionally conservative (pulls
   the score toward zero) and I could not construct a status flip from it, so: latent.
