## Divergences between the briefed property and the code

The brief asked for five properties; two of them are literally false against the
code as designed, and one needed restating on a different field. The harness
prints a `DIVERGENCE` line for each instead of quietly passing:

1. **"Adding any disputed record never changes confidence or status."**
   False by design: `directional_groups` excludes disputed records, and
   `decide(..., disputed_support=…)` re-runs the label with them counted and
   downgrades to `PARTIAL` when that would change it. A disputed record is
   therefore *not* inert — it is deliberately decision-relevant. The harness
   asserts the true invariant instead: a dispute may never strengthen a verdict.

2. **"Adding one independent support group never lowers confidence."**
   True of `evidence_score`, false of `confidence`, because confidence is
   `abs(score)`. Concretely: one contradiction alone is confidence `0.5`; add one
   supporting group and the score rises from `-0.5` to `0.0` while confidence
   falls to `0.0`. That is the defect the signed score was introduced to fix —
   the earlier table genuinely *inverted* (0.58 → 0.52). Asserting the briefed
   wording on `confidence` would fail for a correct implementation, so the
   monotonicity property is stated on the signed score and the confidence drop is
   asserted separately as intentional.

3. **"`contested` is true exactly when both directions have a fresh accepted
   record or a decision-relevant dispute."**
   The "decision-relevant" qualifier is narrower than the code: `contested` is
   `(s > 0 and c > 0) or disputed > 0`, so a dispute that cannot change the label
   still sets the flag. Defensible — the flag means "a human contested something",
   not "the verdict moved" — but the two meanings should not be confused, hence
   the divergence line.
