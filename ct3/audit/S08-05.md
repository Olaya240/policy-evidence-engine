## Error codes actually observed

All four refusals report **`code="invalid_assessment"`** — the `AssessmentError`
default, because none of the `challenge` messages passes a `code=`:

| Refusal | message |
|---|---|
| unknown record id | `Source record was not found` |
| restricted record | `Source record was not found` (identical — no existence oracle) |
| quote absent from record | `Challenge quote must be an exact source substring` |
| two-character quote | `Challenge quote must be an exact source substring` |
| valid record, no candidate | `'<hypothesis>' is not an assessed dependency` (hypothesis interpolated) |

So `code` alone cannot separate "malformed quote" from "record does not exist"
from "record you may not see". The tests assert the observed code so that a
future split is a deliberate, visible change; they also assert the message, which
is what actually distinguishes the cases today. Not changed here: the error
contract is shared with `investigate` and the routes, so a code split belongs to
whoever owns that surface.

## Read-only observations

1. Case 6's guarantee is "not double counted in the evidence list", not
   "idempotent": `version` still increments on the second challenge of the same
   record, so a caller that retries a challenge twice gets `version + 2` for one
   disputed item.
2. The version bump is unconditional and the status/confidence are recomputed
   from the whole evidence list, so challenging a record whose assessment is
   NEUTRAL still moves `version` and the trace while changing no disposition.
3. Case 8's message interpolates the hypothesis key; the assertion matches on the
   stable suffix only.
