## Caller-by-caller

**`main.py:20` — `AssessmentEngine()`.** Passes no clock, so every trace timestamp
is wall clock. The module-level engine is shared by all requests; `__slots__` plus
`_sealed` is what stops a request handler rebinding `provider` or `clock`. That is
respected by every caller I read: nothing in `app/` assigns to an engine attribute.

**`evaluate.py:61` — `AssessmentEngine(semantic_guard=guarded, clock=lambda: EVALUATION_AS_OF)`.**
Supplies a fixed clock and then compares two `challenge` calls for byte equality
(`72-73`). This is the only caller that depends on the purity the clock was added
for, and it depends on it in the strongest form: any new wall-clock read inside
`investigate`/`challenge` breaks it. `evaluate.py:171` constructs a second engine
**without** a clock; the two are used in the same evaluation, so an outcome recorded
under one is reproducible and the same outcome under the other is not. Intentional
where it is a deliberate contrast, but nothing in the code says so.

**`main.py:124` — `engine.investigate(records)` / `assess_hypothesis(records, …)`.**
`records` is a fresh `store.list_records()` per request, so an engine that mutated
the list would corrupt one request, not the store. No precondition is documented on
`records`; the engine's willingness to hold references to those `Record` objects in
the returned claims is the contract, and `store.create_investigation` re-serialises
immediately.

**`main.py:154` — `engine.challenge(claim, records, …)`.** `claim` comes from
`snapshot["claims"]`, and the same dict is then passed to
`store.apply_challenge(..., expected_claims=snapshot["claims"])`. This caller is
correct only if `challenge` does not mutate `claim`; `test_legacy_challenge.py`
exists precisely because it once did. The precondition is therefore load-bearing in
the HTTP path and is stated nowhere in `challenge`'s signature — the copy is an
implementation detail the caller cannot see.

## Ranked findings

1. **`zip(evidence, evidence_evaluation_times)` silently truncates.** The
   `staleness_policy.evidence_evaluation_times` list iterates that `zip`, so a caller
   passing a shorter list produces a trace whose staleness section covers fewer
   records than its `evidence_dispositions` section, with no error. The `challenge`
   caller rebuilds its evidence list (`evidence_models`, 553) before the call at 599;
   whether the two lists are always the same length there is slice 8's question, and
   this report does not settle it. `Inferred` from the comprehension; one length
   mismatch probe settles it.

2. **One trace can name two different records as "dependent".** `_build_explanation_trace`
   emits `dependent_support_records` from `decision.dependent_support_ids` and
   `evidence_dispositions` codes from `_evidence_dispositions`, which *recomputes*
   dependent ids as `members[:-1]` over `decision.supports` (238-241). Both derive
   from list order, so they agree today only because both read the same ordered list;
   a permutation inside `_summarize_status_decision` (e.g. sorting supports for
   determinism) would make the trace contradict itself while every test that checks
   one field still passes.

3. **`_provider_assess` checks the allowlist after exposure, not before.** It builds
   `indexed` from `eligible_provider_records(records)` (398-399) and then calls
   `self.provider_boundary.assess(records, …)` with the **unprojected** list (401);
   the `indexed` map only rejects a citation later. Today the boundary projects
   (slice 5), so nothing leaks — but the guard is defence in depth that only holds
   because of a different file's behaviour, and the comment above it ("final
   permission boundary before any provider sees records") describes an ordering the
   code does not implement.

4. **`_iso_utc` assumes the host timezone for a naive datetime** (`astimezone` on a
   naive value). Slice 6 normalised `Record.timestamp` and the evaluation clock
   inside `_validate_assessment_with_time`, but `generated_at` comes from
   `self.clock()` and `evaluate.py`'s `EVALUATION_AS_OF` is not normalised at the
   construction site. A naive clock would shift every trace timestamp by the host
   offset — silently, and only in the trace, so no assertion on status would notice.

5. **`summarize_status` has no production caller.** It is the documented "established
   public result" and only tests import it. That is not a defect in itself, but it
   means the tuple's shape is pinned by tests rather than by use, and its
   `conflicts`/`missing` lists are the decision's own list objects handed to any
   caller that wants to mutate them.

6. **`department_diversity_uses_last_support_record_per_group: True` is a constant in
   the trace** while `diverse` is computed and read by nothing after the signed table
   (slice 6). A consumer of the trace is told a rule applied that cannot move the
   verdict; the field is provenance for behaviour that no longer exists.
