## Findings

**F1 — `InvestigationCreate.question` enforces its 8-character floor on the raw
string, then strips.** `"        x"` is 9 characters, validates, and is stored as
`"x"`. [Observed — `tests/test_models_slice17.py::test_investigation_question_length_is_measured_before_strip`;
source models.py:110-120.] Every later reader of `Investigation.question`
(including `_derive_preset_id`, main.py:66-79) can therefore receive a
1-character question despite the visible `min_length=8`. Severity: low — the UI
sends preset questions; the floor is not a security control.

**F2 — `ChallengeCreate` does not forbid extra fields; `InvestigationCreate`
does.** `ChallengeCreate(reason=..., source_record_id=..., quote=..., stance=...)`
validates and drops `stance`. [Observed.] A client that believes it is setting a
stance gets a 201 and no stance. Asymmetry is unexplained in the file; the
`forbid` exists one class away at models.py:108.

**F3 — The review-state enum has no `REJECTED`, and `ACCEPTED` is the default.**
[Read — models.py:15-17, :70.] The provider path cannot inherit the default:
`engine.py:78` passes `review_state=EvidenceReviewState.UNVERIFIED` explicitly.
Any other construction (test fixture, replayed snapshot, new caller) produces
*counting* evidence with no review step. Whether `store.py` reconstructs
`Evidence` from persisted rows without that explicit state was **not** checked in
this slice.

**F4 — `Evidence.source_group` is unvalidated and is the sole independence key.**
`decision_table.py:162` and `engine.py:141-146` group by
`source_group or source_record_id`. Seed record `OPS-112` carries
`source_group="OPS-105"` (`mock_provider.py:24`), which is exactly the mechanism
that stops a copied recap counting as a second source. So the field is not
cosmetic: a wrong value silently changes how many independent sources the status
rule sees. [Read — the four citations.] Blast radius is bounded: records enter
only from `mock_provider.py` constants and `store.py:133`; the endpoint list in
`main.py` is `GET /api/health`, `GET /api/records`,
`POST/GET /api/investigations`, `POST .../challenge`, `GET .../history` — there is
no record-ingest endpoint, so no client reaches this field. Second half checked:
`INSERT ... INTO records` appears once in `app/` (`store.py:133`, the seed), so
there is no second write path there. Whether a script or fixture outside
`app/` writes the same table was not checked.

[Read for the model column; **Observed** for the accepted values — `test_unvalidated_fields_that_reach_the_engine_are_the_expected_set`.]
A direct `Evidence(...)` in any future code path skips every engine-side guard.

**F6 — `Record` is served cross-origin with `tags` and `restricted`.**
`main.py:18` allows `http://localhost:5174` and `http://127.0.0.1:5174`;
`main.py:104` returns `response_model=list[Record]`. Every `Record` field crosses
that boundary. `tags` is never read by a rule — across `backend/app/*.py` it occurs
only in `mock_provider.py` seed literals, `store.py` persistence, and the model
itself — so it is verdict-irrelevant payload. `restricted` is verdict-relevant
(`access.visible_records`, `engine.py:508`) but is only ever serialized as
`False`, because true rows are filtered before the response model sees them.
[Read — citations above; the `tags` absence is bounded to `app/*.py` attribute and
key access, not to the frontend.]

**F7 — Preset maps are total and consistent (this one is clean).**
Both maps cover all four `InvestigationPreset` members; the four mapped
hypothesis ids exist in `HYPOTHESES` and are distinct; the four canonical
questions are distinct, non-blank, and each is a legal
`InvestigationCreate.question`. `main.py:117` / `:121` index both maps with a
value that came from the enum, so a missing key would be a `KeyError` (500) on
the creation path rather than a 422 — the invariant that prevents it is now
tested. [Observed.]

**F8 — `_derive_preset_id` couples a claim's id to its hypothesis id.**
`main.py:76-77` requires `claim.id == hypothesis_id == claim.hypothesis_id` to
recognise a preset. That is a model-shape assumption (claim id == hypothesis id)
stated nowhere in `models.py`, where `Claim.id: str` and `Claim.hypothesis_id: str`
are independent free strings. [Read — main.py:66-79, models.py:82-83.] Flagged,
not fixed: outside this slice's file.
