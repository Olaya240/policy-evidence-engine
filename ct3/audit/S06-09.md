## False or stale statements

**1. Line 1 — `"""Deterministic evidence validation, status calculation, and dependency recomputation."""`**

False on the default path. `_validate_assessment_with_time` defaults `now` to
`datetime.now(timezone.utc)` (line 50), and `evaluated_at` is stamped into evidence
and every trace. Two identical calls with a default engine differ. Determinism holds
only when a clock is injected — the exact defect the evaluator caught at 6/7 before
the clock was introduced.

Correction: `"""Evidence validation and status calculation. Deterministic when a
clock is injected; wall-clock stamped otherwise."""`

**2. Lines 132-133 — `# One signed score replaces the ordered branch table. The proofs are in ct3/DecisionTable.v; app/decision_table is the same rule in Python.`**

Overclaim. "The same rule" is true for the thresholds and the score, and false for
two things the Python does and the Coq file does not model: the dispute downgrade
(`decided` with `disputed_support`/`disputed_contradiction`) and group deduplication
before counting. `ct3/W9-proof-gap.md` lists both. A reader who trusts this comment
will believe a proved rule is running, including the parts that are not proved.

Correction: "…the same thresholds and score; the dispute downgrade and group
deduplication are Python-only and untested by the proof."

**3. Line 117 — `diverse = len({getattr(e, "department", None) …}) > 1 if departments_by_source else False`**

Dead after the table swap: nothing reads `diverse`. The name and the presence of
`departments_by_source` (line 116) assert that department diversity moves the
verdict — it did under v1 (0.78 vs 0.68) and no longer does. A reader would very
reasonably believe diversity is still scored.

Correction: delete both lines, or expose `diverse` as a reported fact rather than a
score input, and say which.

**4. Line 65 (`confidence: float`) and line 72 (`evidence_score: float`)**

Neither field is documented, and their meanings are now different in kind: `confidence`
is `abs(score)` — a magnitude that is identical for one source for and one source
against — while `evidence_score` carries the sign. `_StatusDecision` has no docstring
at all, and it is the object the entire explanation trace is built from.

Correction: a class docstring stating that `confidence = |evidence_score|`, that it is
meaningless without `status` or `evidence_score`, and that `contested` is orthogonal
to both.

## The one structural documentation gap

`_StatusDecision` (lines 63-88) is the contract between the decision table and the
trace builder, and it is the only type in the range with no docstring. Every field
that changed meaning in this work — `confidence`, `evidence_score`, `contested`,
`status_rule_id`, `confidence_rule_id` — changed there. A docstring on that class
would have made the v1→v2 change reviewable in one place.
